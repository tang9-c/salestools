# 正式评估与报告

## 提交

1. 用户明确要求正式评估后，始终先调用 `get_company_profile` 校验并保存主体；简称仅用于寻找候选。
2. 用户已给法定名称与信用代码且返回唯一双字段匹配时直接继续，无需再次确认。否则展示名称、信用代码、状态和地域，让用户选定；已选定的主体不重复询问。字段不匹配则说明差异，不提交。
3. 默认复用缓存；只有明确要求刷新、重新采集或忽略缓存时用 `force_refresh=true`。
4. 保存并展示返回的 `assessment_id`；预计耗时只引用服务端实际提供的值。

## 进度与失败

用户单次要求查看进度时调用一次 `get_assessment_status`。
`processing` 是正常异步状态，返回 ID 与当前状态，不自动无限轮询。
用户明确要求持续等待时，仅使用当前环境实际支持的等待/监控方式；会话结束后自动通知必须有已验证可用的持久机制。
失败时报告返回原因，不自行推断凭证或配额问题；未授权刷新不重新提交任务。

## 读取与解释

`get_assessment_report` 未完成时只报告状态；完成后呈现服务端报告，不修改原评级或补造来源。
来源的 `partial/failed` 与任务是否完成分别判断。关键结论引用已有链接和依据；信息不足可保留“待核实”。

综合机会、推荐产品与七产品机会沿用服务端结果。融资不能称预算落实，招聘不能直接称采购意向，行业标签不参与评级。
关联更新使用 `include_related_updates:true`，规则见 [企业关联与历史](../../salestools-contact-management/references/company-context.md)；原报告正文保持原样。
