# 名片任职关系最小修复验证

## 修复边界

姓名、公司、职位唯一且归属清楚的名片，可以提取正式 `worksFor`，保留职位与文件引文；不要求另有“任职于”字样。不推断任职日期，入库的 `employment_status` 保持 `unknown`，不表示已核实当前在职。

多人物、多公司、缺职位或版面归属不清时，仅保留待核实组织线索。合成测试标识不是任职证据，也不否定测试名片声明的关系；测试结果不能作为真实人物事实。

仅调整提取提示、测试和 PRD。现有提交逻辑已经允许有来源的无日期任职关系，因此未修改接口、数据库、Rust 存储或部署配置。简历日期校验不变。

## 真实模型验证

直接运行本地源码中的 `DocumentExtractor`，使用服务配置的真实方舟模型，输入合成文本块。未经过图片 OCR、远端 MCP App 或正式入库。

旧规则对清晰名片返回无任职关系，复现问题。初版修复仍将测试标识当作反证，并误接纳双公司名片；最终提示修正这两项后，以下五个样本均通过：

| 样本 | 结果 |
| --- | --- |
| 唯一姓名、公司、职位 | 生成 `worksFor` 与职位，不生成日期 |
| 同上，包含合成测试免责声明 | 生成相同关系，不把免责声明作为任职引文 |
| 两家公司 | 不生成 `worksFor`，保留待核实信息 |
| 没有职位 | 不生成 `worksFor`，保留组织线索 |
| 有日期的简历任职 | 保留原文起止月份 |

有限样本说明本次提示在这些输入上有效，不保证所有名片都能正确识别。
