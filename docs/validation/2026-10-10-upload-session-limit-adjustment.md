# 上传会话限制最小调整

## 问题与取舍

每 userId 最多两个活跃上传会话，且没有查看旧会话的入口；关闭页面可能留下两小时有效的会话，阻止用户再次打开入口。上传会话不等于解析任务，不能用此限制替代实际导入资源保护。

## 本次修改

- 取消每用户两个活跃会话的限制，改为每个应用进程最多 1000 个活跃上传会话，沿用现有容量错误码。
- 创建会话之前继续清理到期及来源 Token 已失效的会话；成功入库和显式退出继续释放对应会话。有效期仍为创建后两小时。
- 总容量不足时提示稍后重新打开入口，不再要求用户寻找不可查看的旧会话。
- 不新增配置、工具、会话管理页面或自动撤销；不改用户鉴权、文件限制、导入并发、任务超时和已有联系人。

## 验证

测试覆盖同一用户第三个会话可创建且不撤销第一个、跨用户累计达到总上限、退出后兑换未消耗的入口、到期及完成后释放容量、容量 HTTP 返回与脱敏日志、页面容量提示及恢复流程。

## 边界

1000 是进程级内存保护，不是用户配额；多个进程各自计数，重启会丢失内存中的会话。单个用户仍可能占满总容量。备用网页多标签页 Cookie 覆盖问题由后续[独立修复](2026-10-10-upload-cookie-tab-isolation.md)处理。部署及远端真实宿主验收须在发布后另行进行。
