# 上传入口容量错误最小修复

## 证据

新建远端入口立即兑换返回 401/HANDOFF_INVALID（184 ms），不能认定为用户打开过慢。现有 UploadSessions.exchange 吞掉 create 的所有异常，本地复现两个活跃会话下容量错误被伪装为入口失效。线上是否确实达到容量，旧返回值不足以证明。

## 修改

- 容量不足明确返回 429/UPLOAD_SESSION_CAPACITY；不撤销其他会话、不增加上限。
- 容量失败不消耗短时入口，也不延长原有 60 秒有效期；成功兑换仍只能使用一次。
- 真正失效仍返回 401/HANDOFF_INVALID，未知内部异常返回 503/UPLOAD_SESSION_UNAVAILABLE。
- 失败日志仅含固定 event、时间、结果、错误码和 HTTP 状态；不包含入口 code、Cookie、Bearer、用户信息或异常原文。
- 页面提示已有两个会话，需要在其他上传页面点击退出；不再错误提示失效。URL 中的短时 code 只在兑换成功后移除。

## 验证

- 两项新增/调整回归测试先失败，修复后会话与 HTTP 两文件 88 项通过。
- Chromium 使用解释器执行页面源码（未构建）：新增容量文案、保留 hash、释放容量后成功兑换并清除 hash 的浏览器测试通过。默认 Playwright 缓存版本缺失，指定本机已安装 Chrome 完成验证。
- 类型检查和 diff 检查通过。未执行 bundle、完整容器 CI，未提交、推送、发布或部署。模拟网页验证不等同于真实 Codex MCP App 宿主验收。

## 运维边界

部署代码后仍需用户显式退出旧上传会话，或等待两小时 TTL；若旧页面凭证已丢失，本次不新增管理员清除接口，也不自动撤销活跃任务。多实例内存会话不共享仍需单独核实，不在本次修复范围。
