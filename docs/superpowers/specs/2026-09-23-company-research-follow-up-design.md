# 单企业定向追问功能设计

## 目标与边界

在固定七产品报告之外，允许销售对**已确认法定主体**提出一次性自然语言问题，例如“这条 SolidWorks 招聘究竟支持什么结论？”或“近一年有哪些产品发布、招聘和扩张信号？”。借鉴 Clay 的 Research any account，但首版只研究单个主体，不建设多轮 Agent、跨企业搜索、持续监控、追问历史或新的评估队列。

追问是独立的阅读和研究动作：不重跑七产品评分，不修改已有报告、机会等级或推荐产品。招聘岗位只能证明相应岗位或技能需求，不能直接证明软件采购计划；“趋势”仅是带日期的定性时间线，资料不足时不声称人数或招聘量增长。

## 接口与主体校验

新增同步 MCP 工具 `ask_company`，输入为 `legal_name`、`credit_code`、`question`，可选 `assessment_id`。输出包含 `status`（`answered`、`insufficient`、`failed`）、`legal_name`、`markdown`、`used_fresh_research`、`collected_at`（可空）和所引用来源（标题、来源类别、可空 URL、可空发布日期）。成功回答和证据不足均用正常工具结果；输入格式错误仍由 MCP 校验拒绝。

- 每次必须在现有 30 天有效的 `company_profiles` 中按信用代码找到已确认主体，并核对法定名称；不接受仅由调用方声称已确认的主体。不存在或不一致时返回 `failed`，提示先调用 `get_company_profile` 确认；不自动猜测候选。
- 指定 `assessment_id` 时，必须是已完成评估，且名称、信用代码与当前主体一致；否则返回 `failed`。不按提交用户隔离读取，与现有报告权限一致。
- 未指定 `assessment_id` 时，仅选择该信用代码最新一份、完成时间在 30 天内且含证据快照的报告；找不到则直接进行定向研究。指定的旧报告仍可作为定位依据，但过期快照不得复用。
- 返回内容分为“资料直接支持”“可能的解释但未获证实”“仍需核实”。引用只允许使用实际输入证据的 ID；网页给直达链接，企查查无直达链接时标明“企查查记录，无直达链接”，不得编造 URL。

## 证据保存与补查

当前 `assessments` 只保存 Markdown 和审计摘要，无法可靠解释报告中某条证据的原文。为新完成的评估添加可空 `evidence_snapshot_json`，与报告在同一次完成操作中保存。快照由本次评估的 `ResearchBundle` 和 `ReportModel` 按报告引用的 evidence ID 连接生成，仅含对应事实、来源元数据、主体归属以及有限的相关原文摘录；不保存完整上游响应。摘录若被截断，应在快照中留标记。旧报告不回填、不解析 Markdown 猜测原文；没有快照时明确说明并定向补查。

快照以其 `collected_at` 为准，采集后 30 天内可复用；30 天只是复用期，不新增物理删除。为避免做不可靠的中文语义匹配，首版仅在问题明确提及快照中已有的产品名称或来源标题、存在对应的已确认主体事实，且未询问“最新/近期/目前/趋势”等动态内容时，直接用快照；其他情况保守地定向补查。不能把仅匹配集团、子公司或品牌简称的资料当作目标法定主体事实；不确定归属只能列入待核实。

补查最多调用 1 次企查查、2 次豆包搜索、1 次方舟回答，不做完整八主题搜索。企查查仅对问题明确涉及招聘、融资或招投标时选择对应的现有主体工具；其他问题依靠定向网页搜索。模型只负责基于传入材料组织答案，不得自行追加工具调用、改变七产品评级或将网页指令当成命令。模型返回 `claims`，每条包含 `category`（`supported`、`interpretation`、`unknown`）、`text` 和 `evidenceIds`。服务端要求 `supported` 至少引用一条已确认主体证据；`interpretation` 必须明确为推测；`unknown` 允许无引用。任何不存在或归属不符的证据 ID 都不能支持事实结论，再由服务端渲染 Markdown。模型输入受现有 `ARK_REQUEST_MAX_BYTES` 约束；装不下的材料必须计数并在答案中提示覆盖不足。

单次同步工具调用以 60 秒为外部上限，内部预留响应时间并使用请求级取消信号；超时后必须停止本次上游请求，不能仅向客户端返回超时而让后台继续调用。不自动重试。单一来源失败时，如剩余证据足以回答，可返回 `answered` 并明确标注来源限制；没有可确认的相关证据时返回 `insufficient`；主体校验、方舟调用或整体时限失败时返回 `failed`。三种状态均不得伪造结论。新搜索结果和追问答案不另行持久化。

## 测试与验收

- 旧报告已有 SolidWorks 招聘证据：解释岗位使用/技能需求与采购意向的边界，引用正确来源；不触发完整采集，且原报告、评分保持不变。
- 仅有已确认主体画像、没有报告：可定向查询近期发布；无主体画像、法定名称或报告主体不一致时，调用在上游请求前失败。
- 最新报告快照在第 30 天仍可复用，超过即补查；历史报告没有快照、明确指定旧报告或未指定报告时均按上述规则处理。
- 简称仅指向集团/子公司时不归属于目标主体；无日期的资料不能形成有时间顺序的趋势结论；无 URL 的企查查记录不产生虚构链接。
- 单源失败且剩余证据有效时显示限制；无证据返回 `insufficient`；方舟失败或 60 秒时限到达返回 `failed`，并验证上游请求确实取消。
- 新旧 SQLite 均能启动，旧报告仍可读取；新增 MCP 工具不改变现有工具契约。运行类型检查、完整测试与构建。
