# 方舟证据装载与机会报告修复设计

## 背景

当前正式评估把方舟请求限制为 12,288 UTF-8 字节，并额外把研究资料写死为最多 4 条。固定条数会让招聘、采购等动态资料挤掉官网产品和行业证据。行业因而可能被整理为 `unverified`，七项产品全部成为“待核实”。随后 Markdown 渲染器在 `recommendedProduct === null` 时使用降级模板，主动隐藏客户摘要、产品矩阵和关键证据。

企查查来源为 `partial`、融资或年报缺失、企查查没有可点击链接，都不是全局否决条件。它们应作为来源或增强信息缺口呈现，而不是替代每项产品的独立判断。

## 目标

- 取消固定 4 条证据限制，在确定性字节预算内动态装载尽可能多的证据。
- 在任何结果下都显示客户摘要、七产品机会矩阵、关键证据和分层缺口。
- 保存足以回溯行业分类、逐产品判断及方舟选样情况的精简派生 JSON。
- 记录选样数量、请求字节数、类别覆盖和最终判断，不保存网页正文或上游原始响应。
- 保持现有确定性机会规则、上游调用次数、鉴权和单进程队列不变。

## 非目标

- 不引入 RAG、向量数据库、多轮 Agent、多模型评审或 PostgreSQL。
- 不保存企查查、豆包搜索或方舟原始响应。
- 不因为来源为 `partial` 或缺少 URL 自动降低产品等级。
- 不在缺少真实调用证据时宣称方舟官方容量上限。

## 设计

### 1. 动态证据装载

以 `ARK_REQUEST_MAX_BYTES` 作为唯一公开容量配置，默认 12,288。客户端在加入请求信封和系统提示词后检查最终请求字节数。装载器按剩余预算动态选择证据，不再使用 `MAX_ITEMS`。

装载器先为四个类别各尝试保留一条：

1. `industry`：官网产品、企业简介或明确行业资料；
2. `technology`：招聘、软件生态、工程方法、专利；
3. `timing`：采购、招投标、扩产；
4. `capacity`：融资、组织规模、资质、风险。

随后按现有关键词价值和来源交错顺序填充剩余空间。每个候选从完整来源元数据开始，优先保留摘要和关键词窗口；空间不足时逐步缩短正文、摘要，最终才排除该条。选择顺序必须稳定。

返回额外的选样统计：原始数量、入选数量、排除数量、各类别入选数量、紧凑 ResearchBundle 字节数。容量 gap 使用实际 `N/M`，只有发生缩减或排除时才加入。

### 2. 机会判断与报告

现有机会规则保持不变。报告层不再把 `recommendedProduct === null` 当作隐藏主体内容的条件。所有完成报告统一包含：

- 客户摘要；
- 七产品机会矩阵；
- 关键证据；
- 销售建议或“暂不推荐”；
- 风险与分层缺口；
- 来源状态。

缺口按文本语义分为：`rating`（决定无法评级）、`enhancement`（影响高机会条件）和 `audit`（来源、链接或容量告警）。分类只改变呈现，不改变确定性评分。

### 3. 精简结果审计

`assessments` 增加可空的 `result_json`。SQLite 启动迁移使用 `ALTER TABLE` 兼容已有数据库。JSON 固定保存：

- `industry_classification`、`industry_evidence_ids`；
- 七项 `opportunities`；
- `selected_evidence_ids`；
- `original_evidence_count`、`selected_evidence_count`、`excluded_evidence_count`；
- `selected_category_counts`；
- `ark_research_bytes`、`ark_request_bytes`。

`recommended_product` 与 `overall_opportunity` 继续保存于 `assessments` 的独立列，不属于 `result_json`。不保存证据正文。任务服务仍以原有少量顶层字段响应，避免扩大 MCP 契约。

### 4. 日志

在现有普通 JSON 日志中新增一次评估决策事件，包含 assessment ID、证据数量、类别覆盖、请求字节数、行业分类和七产品等级。日志不得包含网页正文、Token 或上游原始错误正文。

## 错误处理

- 单条证据最小化后仍放不进预算：排除并计数，不使任务失败。
- 固定字段和系统提示词本身超过总预算：以 `INPUT_TOO_LARGE` 失败，避免发送不完整请求。
- 旧数据库没有 `result_json`：启动时幂等增加列。
- `result_json` 无法序列化或不满足内部合同：任务失败为“体检报告生成或保存失败”，不保存半成品。

## 验收

- 超过 4 条的小型证据可以在预算内全部送入方舟。
- 当存在行业证据时，四类最低覆盖不会让它被动态信号挤掉。
- 最终请求不超过配置的字节数，同一输入选择结果一致。
- `recommendedProduct === null` 时仍显示客户摘要和七产品矩阵。
- QCC 链接缺失、融资失败或年报失败不会在报告层隐藏产品判断。
- SQLite 可查询精简 `result_json`，其中不含来源正文。
- 12KB、24KB、48KB 真实调用分别记录成功、延迟、选样数和 JSON 合同结果；只有用户已配置真实凭据时执行。
