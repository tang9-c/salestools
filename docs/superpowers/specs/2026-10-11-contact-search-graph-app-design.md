# 联系人搜索图谱 MCP App 设计

日期：2026-10-11。状态：开发分支已实现并完成本地无构建验证；远程 CI、生产镜像与真实宿主验收待执行，不视为上线完成。

## 1. 目标与入口

用户在聊天中说“在联系人库里找云杉智造的联系人”，调用 `search_contacts` 后，支持 MCP Apps 的客户端可展示独立的“联系人图谱”界面；不支持的客户端继续读取原 JSON，由聊天模型解释。

不新增 `open_contact_graph` 工具。`search_contacts` 的输入、`content` 文本 JSON、`structuredContent`、默认筛选、排序与分页语义不变，只增加 App 资源关联。宿主决定是否展示或需要用户展开，不能承诺所有客户端自动打开。

首版是当前搜索结果的只读局部图谱，不是全库浏览器。打开 App 后自动显示当前搜索页所有命中节点及其全部直接关联节点和边，包括入向和出向正式关系；只读取命中节点的一跳关系，不递归展开补充节点。点击节点用于详情和证据，不是显示首层关系的前提。

## 2. 已核对的现状

- `src/mcp/contact-search-tools.ts` 注册 `search_contacts`，返回节点摘要和分页信息，不包含完整关系。
- `src/contacts/contact-search.ts` 已支持关键词、姓名、职位、技能、组织 ID、可选待核实线索及语义/混合搜索，不在本次修改搜索算法。
- `src/mcp/contact-tools.ts` 的 `get_contact` 返回实体属性、正式关系、短证据、冲突和待核实项；三个集合各有独立分页游标。
- Rust `get_contact` 中 `relations` 与 `unverified_claims` 是不同集合，不能混用。关系证据包含在独立的 `evidence` 分页中，并不保证首屏就有某条边的证据。
- `src/mcp/tools.ts`、`web/contact-upload.*` 已使用 `@modelcontextprotocol/ext-apps`；现有页面打包使用 esbuild，Dockerfile 已复制整个 `web/dist`。
- 远程“云杉智造”测试默认只命中公司；包含待核实线索时才返回林知远，旧档案没有正式 `worksFor`。图谱必须忠实呈现这一差异，不能用姓名或职位补出任职边。

## 3. 范围与取舍

采用自包含 HTML + TypeScript + SVG，不增加 React、图可视化库、CDN 或布局服务。节点按人物、机构、项目分列，使用确定性初始位置；保留平移、缩放和适应画布，不做节点拖拽、重叠线避让、布局重置或力导向求解器。

复用现有 MCP 宿主鉴权和 `App.callServerTool`，不新增 HTTP 查询路由、Bearer 传递、上传会话、Cookie 或备用网页入口。没有 MCP 宿主桥接的普通网页不能查询数据，应明确显示“请在支持 MCP App 的聊天中打开”。

不修改 Rust、SQLite 表、图谱 ontology、索引或历史记录。不增加 LLM 调用、上游搜索、写工具、关系审核、监控或持久化 UI 状态。现有混合/语义搜索可能调用已有 embedding 服务；本次图谱展示本身不调用模型。

## 4. 展示与交互

### 4.1 首屏

标题“联系人图谱”；显示实际搜索条件、搜索匹配总数、当前页条数及 warnings。主体为 SVG 图谱，旁边/下方为可键盘操作的节点列表和详情面板。

首次收到 `search_contacts` 结果先画当前页命中节点，再顺序调用 `get_contact` 自动读完每个命中节点的关系分页，逐页补入直接关联节点和边。不等待全部请求结束才绘制。按命中节点显示“加载中/加载完成/部分失败”，并显示已完成节点数；只有全部允许的关系分页成功读完，才能称“一跳关系加载完成”。加载中或失败时不得把无边解释为无关系；完成且没有允许的关系时提示“未返回职业范围内的直接关联”。

- Person：人物样式；Organization：机构样式；Project：项目样式。
- 名称优先取返回的 `display_name`/`name`，未具名使用现有 ID 后缀，不虚构名字。
- “搜索命中”与“展开补充”分别标记；补充节点不计入搜索 `total`。
- 查询得到 Organization 时必须显示，不自动过滤为人物或把公司节点称为联系人。
- 没有结果时显示“本次库内查询未找到匹配记录”，不声称企业或人员不存在。

### 4.2 自动一跳加载与节点详情

自动加载仅以当前搜索页命中 ID 为根。每个根的正式关系分页独立使用返回的 next_offset，读取到结束；启用待核实项时，其 claim 分页也读取到结束。后台加载使用 evidence_limit=1、relation_limit=20，claim_limit 根据原查询参数为20或0；沿用现有最小limit，不为画边自动加载全部证据。关系和claim分开翻页，非目标集合只取最小量并忽略，不将重复返回计入进度。保留本次搜索页累计的允许关系/claim，换搜索页或新查询后清空，不建立跨查询缓存。

端点名称和类型先复用搜索结果、已读实体或返回的明确档案字段；缺失时暂画“未加载档案 · ID 后缀”。关系加载后，顺序读取每个未知端点的 get_contact（evidence_limit=1、relation_limit=1、claim_limit=0），只补名称和类型，忽略附带关系，不继续遍历。每个端点 ID 在本查询页只补读一次；失败保留占位并提供重试，不按 ID 前缀猜类型。

用户点击节点时通过 `get_contact` 读取所选节点详情：

```json
{
  "entity_id": "选中节点的真实 ID",
  "evidence_limit": 10,
  "relation_limit": 20,
  "claim_limit": 20
}
```

`claim_limit` 仅在已收到原搜索参数且 `include_unverified:true` 时为 `20`，否则为 `0`。参数尚未收到时，自动加载正式关系，但显示“原查询参数尚未收到，待核实线索未加载”，不能显示成“无待核实线索”。参数随后到达且值为 true 时，自动补读当前搜索页各命中节点的全部 claim 页，不重新读取已完成的正式关系。参数为 false 或未设置时，不读取或展示 claim。

详情只保留一个选中节点和当前三个集合页；切换选中节点不删除已加载的一跳图，也不追加该补充节点的其他关系。当前已加载详情重复点击不重读。全部工具调用串行，使用页面内简单遍历，无通用调度器或并发队列；用户查看详情/证据优先在当前请求结束后执行，自动加载随后继续。失败保留图和此前成功详情，标记失败步骤并允许手动重试。

正式边必须来自 `relations`，身份由 `relation_id` 确定，端点严格使用 `source_id`/`target_id`，保留方向。不能根据搜索命中理由、名字、`jobTitle` 或 `matched_project_id` 独立创建正式边。项目客户命中只是提示，可供用户点击该真实项目 ID 补查，再从详情中读取两跳关系。

实线、虚线共用一个职业关系白名单：`worksFor`（任职于）、`alumniOf`（就读于/校友关系，不声称毕业）、`memberOf`（参与）、`clientOrganization`（项目客户）、`affiliation`（关联）。其他类型的正式关系、claim、证据及冲突不在本 App 展示；可提示用户在聊天查看完整档案，不自动展开家庭关系网络。

补充节点不成为新的自动加载根。点击它只查看详情；详情中的其他关系不进入画布，防止一跳变成递归网络。节点按真实 entity_id 合并，边按各自记录 ID 合并，同名不同 ID 不合并。

### 4.3 待核实关联

已确认原搜索包含 `include_unverified:true` 时，自动读取的 `kind=relation`、`status=unverified`、`relation_type` 属于同一职业关系白名单、`subject_id` 等于正在读取的搜索命中主体且具有明确 `target_id` 的 claim 才可画虚线。正式边须有该命中主体作为一端。边身份使用 `claim_id`，与正式 `relation_id` 分开去重。现有 get_contact 仅返回该主体的 claim，不返回其他主体指向它的入向 claim；不得声称加载了全部入向待核实关联。本次不新增反向 claim 查询。

无真实 `target_id`、仅有目标名称、职业相关字段待核实或 `$experience` 时，仅放入“待核实线索”列表，不创建假节点或边。列表也按同一职业范围过滤，婚姻、亲子及个人联系方式线索不显示。`claim_ids` 可能属于 Person 和 Project；只按当前已读取档案中实际返回的 claim 展示，不将一个人的线索冒充项目线索。

虚线标注“待核实关联”，不把缺少直接陈述的 `affiliation` 改名为任职。点击后展示原始原因与短来源；“合成测试名片”之类的引文即使质量较差也如实展示，不在 UI 中修改记录。

### 4.4 状态、来源与隐私

实线表示“正式图谱关系”，不表示人工核实。`worksFor.metadata.employment_status` 分别显示现任（附 `status_as_of`）、已结束或当前任职未知；无结束日期不等于现任。

节点默认只显示名称、类型和已读取的职位。电话、邮箱、地址、婚姻等不放在画布、标签或提示框；首版详情只展示姓名/机构/项目名、职位、技能、职业相关关系、必要短证据、冲突和待核实线索，不开发完整个人档案编辑器。字段证据和冲突只展示 name/legalName/jobTitle/skills，关系证据只展示职业白名单边的证据；不把 get_contact 的所有证据直接列出。隐藏 UI 字段不是服务端数据脱敏，现有工具仍可能向已鉴权宿主返回完整档案。

节点或边点击后的证据面板按 `subject_kind`、`subject_id` 和必要 `field_path` 对齐，不把实体姓名证据当作关系证据。证据当前页未包含所选边时提示“当前证据页未包含该关系的证据”，提供证据翻页；不能误称关系无证据。

所有服务端字符串用 `textContent`/SVG 文本节点，不拼接 `innerHTML`。来源链接只允许 `http:`/`https:`，由用户显式点击，通过宿主链接接口打开，失败时展示可复制 URL；不自动访问来源、加载头像、图片或外部脚本。不把整份 `get_contact`、凭证或个人字段写入 console、localStorage、sessionStorage 或遥测。

## 5. 分页、范围与失败

- 搜索“下一页”保持原参数，只用返回的 `next_offset` 更新 `offset`，下一页替换当前画布并清空当前选中详情；“上一页”仅记录已成功读取的页起点，不缓存结果正文、不自行推算游标。宿主传入新查询同样重置。首版不另做页面内高级搜索表单，用户在聊天修改条件。
- 原搜索参数未从宿主到达时，当前结果仍可显示，搜索分页禁用并提示重新在聊天发起搜索；不猜测参数执行全库查询。
- 自动一跳加载逐根累计全部关系页及允许的 claim 页，不能在20条处截断。游标不前进或重复时停止该集合并标记响应异常，防止死循环；其他根继续。失败保存该根失败集合与 offset，手动重试从失败页继续，不重读已成功页。
- 选中详情的关系、证据、claim 各有上一页/下一页，使用各自 next_offset；固定 limit 为10/20/20，上一页使用 max(0, offset-limit)。详情集合页替换、不累积，且不改变已自动加载的画布。证据当前页未包含所选边不表示没有证据。
- 画布范围是当前页最多50个搜索命中及其全部允许的一跳端点，不承诺总节点上限，不静默截断。搜索默认10条保持不变，关联多时加载更久；显示进度，提供停止加载及继续加载，保留已成功内容并明确未完成。不新增 `.env` 项。
- 宿主连接及每次只读工具请求的 UI 等待上限为 30 秒，使用 SDK 的请求 timeout；超时不修改服务端任务或承诺后台继续。显示失败步骤及手动重试，保留已成功图形。宿主不支持工具调用时保留搜索节点，提示在聊天查询详情。
- 新查询/成功搜索翻页递增请求序号，停止旧自动遍历并清空旧页关系集合；晚到的旧响应不覆盖新图。保持最多一个未结束的工具请求，新查询在原请求结束/超时后才开始自动加载。每次请求上限30秒不等于整个一跳加载30秒完成，不设置会静默丢边的总调用上限。
- 搜索失败保留旧图并标明上一查询结果。自动加载返回 found:false 时标记该根/端点不可用，不影响其他根，不猜新ID；选中详情失败也不清空整个图。关系有多个根支持时，单个根失败不能删除其他根已返回的同一条边。
- App 刷新后只恢复宿主实际重发的工具输入/结果；无重发则提示在聊天重新搜索，不持久化原档案或创建新的认证机制。

## 6. 接入方式与最少文件

资源 URI：`ui://salestools/contact-search-graph.html`。`search_contacts` 使用 `registerAppTool` 关联资源并允许 model/app 调用；资源通过 `registerAppResource` 注册，自包含 HTML 使用现有 `RESOURCE_MIME_TYPE`。`get_contact` 保留模型可见性，明确允许 App 只读调用，不把写工具加入此 App 的调用路径。

`McpServices` 增加可选 `contactSearchApp: { html: () => Promise<string> }`；在生产 `servicesFor` 的图谱启用分支注入。`registerContactSearchTools` 增加最后一个可选 App 参数；未注入时保留现有 JSON-only 注册，便于旧测试和无资源环境使用。不得给存在的服务器工具静默创建虚假的 App 能力。

新增：`web/contact-search-graph.html`（结构/样式）、`web/contact-search-graph.ts`（宿主桥接/串行加载/交互）、`web/contact-search-graph-model.ts`（当前搜索页及累计一跳材料生成图形的纯函数）。搜索输入与返回类型复用现有服务类型，不重新维护一份搜索契约；详情只校验展示所需字段。不引入通用图框架、通用 API 客户端或复杂控制器层。

扩展现有 `scripts/build-contact-upload.mjs` 为明确的两个入口列表，继续分别输出 `web/dist/contact-upload.html` 与 `web/dist/contact-search-graph.html`。保留脚本名和现有 package scripts，确保上传页面打包不回归。Dockerfile 已复制整个输出目录，不新增容器。

App 在连接前设置 `ontoolinput`、`ontoolresult` 和失败处理。通过 MCP 宿主读取数据，不给资源添加业务域名网络访问许可；不需要公网接口或上传用的 handoff。请求只允许代码中的 `search_contacts`、`get_contact` 两个固定名称。

## 7. 验收

1. 相同 `search_contacts` 输入的 JSON 文本和 `structuredContent` 完全不变；无 App 客户端继续工作。
2. 图谱未启用时不注册图谱 App；启用时能够发现并读取自包含资源，生产镜像包含两个页面。
3. 同页两个无关系人物不自动连线；同名不同 ID 不合并；未知端点不编造名称。
4. 正式任职、教育、人物参与项目与项目客户关系方向正确；未知任职不标现任，教育不自动标毕业。
5. 参数未到时不读取 claim，明确标记未加载；参数到达且允许待核实时自动补读全部命中根的 claim 页。职业范围一致；字段线索不冒充边，入向 claim 能力限制明确。
6. 无需点击即显示所有命中根的全部一跳职业关系，包括超过20条的后续页；共享节点/边去重，补充节点不递归。详情切换/分页不清空图；搜索翻页清空并重新自动加载；旧响应不覆盖，停止/继续和失败页重试正常。
7. 超时、单节点失败、宿主不支持、`found:false`、空结果有正确提示和可用的恢复方式。
8. 恶意姓名/引文/URL 不执行脚本，无自动外部资源请求、写工具或个人信息日志。
9. 远程真实调用“云杉智造”并在当前 Codex 聊天展开 App：默认只有公司命中且不能编造任职；包含待核实时林知远也成为命中根，自动读取后显示待核实虚线，不需点击人物。此案例是真实链路上的合成记录，不等于真实人员资料验证。
10. 复用已有原生存储/查询回归；新增图形渲染 fixture 验证职业/教育/项目边和待核实过滤，资源/JSON 兼容与真实宿主验收验证接入。不新建一整套 Rust 图谱验收，不为了验收修改远程旧测试数据。

## 8. 验证与延期

本地只允许 `tsc --noEmit`、不构建的解释器单元测试和 diff 检查。页面 bundle、真实 SDK iframe、已有原生回归与生产镜像验证在现有远程 CI 执行；模拟宿主通过不能替代 Codex/ChatGPT 宿主验收，分别记录版本、tested SHA、结果与脱敏证据。

延期：补充节点递归展开、跨查询详情缓存与并发队列、节点拖拽/避让、全库图谱、反向 claim 查询、可编辑关系、可视化审核/合并、家庭关系图、独立网页登录、导出、布局持久化、复杂力导向和跨企业发现。

本方案不修复旧名片的待核实归属、不变更公司关键词召回规则，也不自动包含待核实项。库中关系缺失是数据状态，不应在可视化中掩盖。
