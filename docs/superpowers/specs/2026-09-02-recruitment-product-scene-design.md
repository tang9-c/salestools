# 招聘产品证据转产品场景设计

## 背景

真实评估中，招聘正文已经明确出现 SolidWorks，但 Ark 只输出了证据引用，没有形成机会评估可使用的“近期、明确产品招聘事实”，导致产品判断落入“未发现具体产品场景”。行业标签不得参与该判断，也不得因为 `industryClassification=unverified` 降低机会等级或置信度。

## 目标

当已确认法定主体的近期招聘正文明确出现目标软件产品时，将其稳定整理为产品相关招聘事实；同时保留对只有标题、摘要、主体归属不明或历史信息的保守处理。

## 文本优先原则

企查查 MCP 和豆包搜索返回的内容经常是中文段落、招聘材料、网页摘要或不稳定的半结构化文本。首版不试图为每种来源建立完整字段映射，也不要求把所有事实拆成精确字段。MCP/搜索原文应尽量完整地交给 Ark，由 Ark 负责总结、归纳和提炼与销售判断有关的信息。

### LLM 负责的工作

- 从正文、摘要和标题中总结企业产品、研发、质量、制造、软件生态、招聘、招投标、扩产和融资情况；
- 将同一事实的多条文本证据合并为一条简洁中文陈述；
- 从招聘材料中提炼岗位、职责、任职要求和明确的软件/工程方法；
- 从融资材料中总结“有无融资、融资概况和对企业阶段的可用提示”，不强求日期、轮次、金额字段完整；
- 识别文本冲突、主体不一致和信息缺口。

### 仍需保留的薄结构

为了支持审计和确定性机会判断，LLM 输出仍保留最小结构，而不是完整来源字段映射：

- `kind`：事实的大类；
- `productTags`：明确涉及的目标产品；
- `strength`：`direct`、`supporting` 或 `weak`；
- `evidenceIds`：支持该事实的原始证据；
- `entityScope`、`entityMatch`、`matchBasis`：主体归属；
- `statement`：LLM 总结后的中文事实。

这些字段只表达“这条总结是什么、来自哪里、主体是否确认”，不要求复刻网页字段，也不要求把自然语言强行拆成日期、金额、轮次、职位级别等细节。无法可靠提炼时，LLM 应保留原文摘要或写入缺口，不得猜测。

### 确定性规则的边界

确定性代码只负责：

- 校验输出结构和证据引用是否存在；
- 防止 LLM 提升来源的主体匹配等级；
- 检查不允许的推断（例如营收倒推、采购意向和高管人格判断）；
- 基于已确认事实计算产品机会等级。

确定性代码不负责从每个 MCP/网页响应中硬解析融资字段、招聘字段或产品场景字段。产品词、岗位职责和工程方法的识别优先由 Ark 根据上下文完成；本地关键词只用于装箱优先级、容量保护和安全校验，不作为独立业务结论。

## 规则

### 强产品招聘事实

满足以下条件时，Ark 应输出一条事实：

- `kind: recruitment`
- `productTags` 包含正文中明确出现的目标产品
- `strength: direct`
- `entityScope: legal_entity`
- `entityMatch: confirmed`
- `evidenceIds` 只引用该招聘来源
- 事实陈述包含产品词和岗位/职责或任职要求，不添加采购推断

机会评估将最近 365 天内的该事实作为已确认产品场景，并按现有产品规则继续检查工程复杂度、时机、预算、决策权和替代壁垒。

### 弱产品招聘信号

以下情况不得升级为强产品场景，但可以保留为普通证据或软件生态信号：

- 产品词只出现在职位标题或搜索摘要；
- 只有泛化岗位名称，没有产品相关职责或任职要求；
- 只能确认简称、品牌、集团或子公司，不能确认法定主体；
- 招聘发布时间超过 365 天或缺少发布时间。

如果正文内容足以确认产品场景，但发布时间、职位字段或其他细节不完整，Ark 可以输出 `supporting` 事实并保留缺口；不应因为无法精确结构化而丢弃整段文本。

### 与行业标签的关系

`industryClassification` 只用于报告展示和行业标签事实，不参与产品机会评分、推荐产品选择或机会置信度。产品机会只能由产品相关事实及其证据属性决定。

## 实现边界

- 在 Ark 系统提示中明确招聘产品事实的字段要求和强弱分层。
- 在 Ark 系统提示中明确“文本优先、薄结构输出”：优先总结上下文，不要求完整字段映射；无法确认的细节写入缺口。
- 在机会评估测试中增加“行业为 unverified 但近期确认产品招聘仍可评级”的案例，以及“仅标题产品词仍不能升级”的案例。
- 在 Ark 测试中增加中文自由文本招聘材料和融资段落：验证能保留总结事实、来源引用和缺失字段，而不是要求固定日期/金额/轮次字段。
- 不保存 Ark 原始响应，不增加新的持久化字段，不修改五类来源调用预算。
- 若 Ark 仍遗漏满足条件的事实，优先调整提示和示例；只有反复出现同一可证明缺陷时，才增加最小的本地兜底映射。兜底只能使用已确认主体、招聘正文、产品词和发布时间，不生成采购意向。

## 验收标准

- 近期、法定主体确认、招聘正文明确出现目标产品的证据，至少产生低或中级产品机会，不再显示“未发现产品场景”。
- 只有标题/摘要或主体未确认的产品词，不得产生确认产品场景。
- 行业为 `unverified` 时，上述两条结果与行业标签已确认时一致。
- 中文自由文本中无法精确提取的融资、招聘或经营细节，应保留 LLM 总结和来源链接，并明确标注缺口，不得因缺字段而丢弃整条证据。
- 现有全量测试、类型检查和构建继续通过。
