# 联系人文件上传入口设计

## 目标与用户流程

已注册 Salestools MCP 的用户可在 ChatGPT 内嵌页面选择一份 PDF 或拍摄／选择一张名片图片。Codex 等未确认支持 MCP Apps 内嵌 UI 的客户端使用工具返回的短期外部链接。页面上传后自动启动现有导入任务，展示服务端聚合的完整候选与证据；只有用户点击确认，才尝试 `auto_create` 入库。重复建议、匹配失败或截断、多个主体及无可提交主体时，页面停止一键入库并给出 `import_id` 供聊天继续处理。

## 组件与边界

1. 一个模型可见的 MCP 工具返回外部备用链接，并关联 `ui://` 上传页面。内嵌页面通过 App 专用工具创建受限会话；不把长期 MCP Bearer Token 或内嵌会话密钥放进模型可见结果。
2. 外部链接只带 60 秒、单次兑换码。外部页面兑换后使用同源 `Secure; HttpOnly; SameSite=Strict` Cookie；内嵌页面使用仅在内存中的会话 Bearer。两者对应同一种服务端会话：绑定用户、来源 Token、单份文件、最多一个导入任务，固定有效期 2 小时。原始凭证不写入持久存储，禁用来源 Token 后会话失效。
3. 现有 `/contact-files` 继续执行流式大小、格式与预检查。新会话只允许一份成功上传，上传并发原子占位，失败可重试。`UploadStore` 记录文件所属用户；`ContactImportService.start` 在写导入任务前校验归属。文件、任务和会话标识都不是权限凭证。
4. 受会话保护的 HTTP 路由仅启动绑定文件的导入、读取绑定任务完整预览及 `confirmation.allowed/reasons`、提交绑定任务的当前预览版本。复用 `ContactImportService`。服务器在预览和页面确认时复用同一完整预览与自动提交判断；前端按钮状态不是授权检查。
5. 内嵌页面只向配置的 Salestools 域名发无 Cookie 请求；外部页面只用同源 Cookie。所有来自文件和模型的文本用文本节点显示。会话与预览响应不缓存、不记录凭证或原文。

## 现有安全前置项

上传临时文件应离开可备份的数据库卷，放在限额临时存储。现有解析子进程继承完整环境变量，且可访问主服务数据；在扩大对外上传使用前，必须把解析放入无密钥、无数据库卷、无出站网络并受资源限额约束的执行环境。这是独立于 UI 的既存风险，不能靠 MCP App 沙箱解决。

## 失败与恢复

文件过大、格式不支持、容量满、会话过期、上传中断和解析失败在页面分别显示。一次性链接过期后由聊天重新生成。会话过期时，已启动的导入任务仍可用 `import_id` 在已鉴权的 MCP 会话中查看。提交使用稳定 `operation_id`，预览版本变化时刷新预览。

## 验收

自动化验证跨用户文件导入、跨会话预览和提交、链接重复兑换、并发双上传、来源 Token 撤销、伪造 Origin、直接调用提交 API、HTML 注入、文件限制、重试和幂等。在 ChatGPT 验证内嵌选择／拍照／预览／确认，在 Codex 验证外部页面。回归现有 CLI 和 MCP 路径。
