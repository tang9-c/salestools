# 联系人缓存与历史展示设计

## 目标

为 `get_contacts` 增加 30 天透明缓存，并在每家企业下同时返回当前联系人和历史任职证据。查询结果以追加式快照永久保存，但历史记录只表示旧网页曾明确提及该姓名和职位，不能据此断言人员已经离职。

## 公共接口

输入保持不变：

```ts
get_contacts({
  query: string;
  region_hint?: string;
})
```

每家公司新增 `historical_contacts`：

```ts
{
  companies: Array<{
    company_name: string;
    contacts: Array<{
      name: string;
      title: string;
      source_url: string;
      published_at: string | null;
    }>;
    historical_contacts: Array<{
      name: string;
      title: string;
      source_url: string;
      published_at: string | null;
      first_seen_at: string;
      last_seen_at: string;
      status: "historical_evidence";
    }>;
  }>;
  warnings: string[];
  collected_at: string;
}
```

`contacts` 仍最多 10 人，`historical_contacts` 也最多 10 人，按 `last_seen_at` 倒序返回。首次查询没有历史快照时，历史数组为空。接口不增加 `cache_hit`、`cached_at`、邮箱、电话或强制刷新参数。

企业数组仍最多 3 家：先按最新快照顺序返回当前企业，再按历史联系人最近出现时间补充仅存在于历史快照的企业。历史-only 企业的 `contacts` 为空；已有 3 家当前企业时不追加历史-only 企业。

## 缓存与存储

新增追加式联系人查询快照表。每条快照保存缓存键、规范化查询、规范化地域、当前联系人结果、采集时间和入库时间；旧快照不覆盖、不删除。存储内容不包含计算后的历史数组，避免历史结果在快照间递归复制。

查询与地域分别执行 NFKC、首尾裁剪、连续空白合并及英文小写化，再用 `SHA-256(JSON.stringify([query, region]))` 生成缓存键。缺省地域按 `null` 参与计算。因此简称、全称或不同地域不会自动归并为同一企业实体。

同一缓存键的最新快照在 30 天内时，服务读取快照并计算历史结果，不调用豆包或方舟。超过 30 天时执行实时刷新；所有正常结果，包括空结果和部分搜索失败结果，均追加为新快照。上游刷新失败时，如果存在旧快照，则返回最新旧快照并加入“实时刷新失败，使用超过 30 天的历史缓存”警告；没有旧快照时返回现有安全化 MCP 错误。数据库读写错误不伪装成上游失败。

同一进程内以缓存键合并并发请求，保证相同实体的同时查询只执行一次上游流程。缓存为全局公开数据，不按访问令牌隔离。

## 历史计算

当前联系人严格取最新快照。历史联系人来自该缓存键更早的全部快照，并满足：相同规范化企业名、姓名和职位未出现在最新快照中。

历史身份键为规范化后的 `company_name + name + title`。同一个人职位变化时，旧职位作为独立历史证据保留；如果旧身份键重新出现在最新快照中，则从历史数组移除并作为当前联系人显示。

`first_seen_at` 和 `last_seen_at` 分别取该身份键在历史快照中的最早、最晚 `collected_at`。来源采用最后一次出现时保存的来源；同一采集时间存在多条来源时，沿用查询顺序和搜索排名确定的最佳来源。企业名只做规范化精确匹配，不推断简称、别名或法人主体关系。

最新快照未出现某人只表示搜索材料发生变化。即使其进入 `historical_contacts`，状态也固定为 `historical_evidence`，不得标记为“离职”“卸任”或“无效”。部分搜索失败、抽取截断等现有 warning 与结果一起返回，提醒调用方历史归类可能受搜索完整性影响。

## 数据流与失败处理

1. 规范化输入并生成缓存键。
2. 读取最新快照；30 天内直接进入历史计算。
3. 缓存过期或不存在时，执行现有两次搜索和一次逻辑方舟抽取。
4. 正常结果通过严格输出 schema 校验后追加快照。
5. 读取同键历史快照，生成当前联系人及历史证据并应用每组上限。
6. 返回原始 `collected_at` 和原有 warnings；缓存行为保持透明。

损坏或不符合 schema 的快照不得返回，应作为数据库数据错误处理并记录安全化日志。任何持久化路径均不得包含搜索正文、模型原始输出、邮箱或电话。

## 测试与验收

- 验证查询规范化、地域隔离、缓存键稳定，以及 30 天边界。
- 验证缓存命中不调用上游，过期刷新成功后追加而非覆盖快照。
- 验证首次查询历史为空，旧快照中消失的身份进入历史，重新出现后回到当前列表。
- 验证职位变化保留旧职位，历史身份正确计算首次和最后发现时间。
- 验证当前及历史分别最多 10 人，历史按最后发现时间倒序且来源确定。
- 验证部分结果、空结果、上游失败旧快照兜底及无快照失败。
- 验证同键并发合并，不同键互不影响。
- 验证严格 snake_case 输出、历史状态固定、损坏快照拒绝，以及所有输出和存储均不含直接联系方式。
- 运行完整测试、类型检查和构建。

## 明确不做

- 不判断或显示“已离职”“仍在职”等就业状态。
- 不做企业别名归并、跨地域实体合并或企查查主体确认。
- 不提供历史反查、历史分页、清理接口或手动强制刷新。
- 不把历史联系人混入当前 `contacts`。
