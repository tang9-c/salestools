# 产品机会证据召回修复设计

## 背景

2026-09-02 使用真实 QCC、豆包搜索和火山方舟评估“深圳市海柔创新科技有限公司”。正式任务 `f52b2001-e0be-493f-a89a-e35dd60df067` 在约 305.5 秒内完成，主体被识别为 P1 工业机器人企业，融资、专利、招投标和一般产品技术资料均有结果，但七项产品机会全部为“待核实”。

本次真实测试暴露的主要技术卡点是：

1. QCC `get_recruitment_info` 返回主体正确但字段结构未知的中文响应时，适配器直接判为不可读，招聘来源失败。
2. 豆包搜索调用虽成功，查询和结果优先级未稳定获得产品软件、完整招聘 JD 或工程方法证据。
3. 方舟固定请求容量优先保证融资和行业、技术、时机、能力四类覆盖，但没有为明确产品词或招聘/工程方法证据保留位置。215 条研究资料最终只入选 8 条，存在产品证据被容量策略排除的风险。

本设计修复证据进入机会判断前的召回链路，不放宽最终机会评级规则，不以行业标签或企业规模推断产品需求。

## 目标与非目标

### 目标

- QCC 招聘响应结构变化时，只要主体可验证且确有招聘材料，就能以限长非结构化材料继续进入事实整理。
- 豆包搜索继续最多调用 8 次，但查询明确覆盖现有软件生态、两组产品招聘和工程方法。
- 方舟请求继续保持 `ARK_REQUEST_MAX_BYTES=12288`，并尽力保留明确产品词证据以及招聘/工程方法证据。
- 有信号时避免技术性丢失；无信号时保持“待核实”，不强行推荐产品。
- 保持信息获取、证据装箱、事实整理、机会判断和报告输出的现有模块边界。

### 非目标

- 不增加 QCC、豆包或方舟调用预算。
- 不增加第二次模型预筛选，不让模型自行搜索。
- 不建立统一规则平台、向量数据库、搜索索引或新队列。
- 不改变七产品的关键词、工程方法和高/中/低/待核实评级门槛。
- 不保存完整 QCC 原始响应、网页正文或模型完整输入输出。
- 不以一次真实企业测试证明销售判断准确率。

## 方案选择

采用三点定向修复：

1. QCC 招聘材料降级。
2. 豆包固定八类查询优化。
3. 方舟产品证据双专槽。

不采用统一产品信号评分平台，因为会扩大 v0.1 改动面；不采用模型预筛选，因为会增加调用、延迟和失败点。

## 模块与数据流

```text
QCC get_recruitment_info
  ├─ 已知结构 → 现有招聘字段映射
  └─ 未知结构但主体可验证 → 限长招聘 material
                                  │
豆包固定 8 次查询 ─→ 产品词/JD/工程方法优先结果 ─┤
                                  ▼
                    方舟装箱：融资 + 四类覆盖
                              + 明确产品信号专槽
                              + 招聘/工程方法专槽
                                  ▼
                    方舟事实抽取 → 现有确定性机会规则
```

模块职责保持如下：

- `src/upstream/qcc/mapper.ts` 只把真实响应变成可审计研究材料，不判断机会。
- `src/upstream/search/search-plan.ts` 只生成查询意图，不做机会评级。
- `src/upstream/ark/payload-budget.ts` 只在固定字节内选择代表证据，不生成事实。
- `src/opportunity/evaluate-product.ts` 继续执行最终确定性判断，本次不改变其机会门槛。

## QCC 招聘材料降级

### 正常路径

`get_recruitment_info` 首先继续使用现有结构化字段映射。已知响应结构仍生成职位名称、发布时间、薪资、学历、经验、地点等最小字段。

### 降级路径

结构化映射失败后，仅在以下条件全部满足时生成一条限长招聘 material：

- 响应可以验证为已确认法定主体，主体名称或信用代码没有冲突。
- 响应中存在实际招聘记录或招聘材料，不是空结果。
- 响应不是工具说明、解释文本、错误消息或目录信息。

material 规则：

- 单次工具结果只生成一条有界 `ResearchItem`，不按未知数组结构展开。
- 内容使用稳定 JSON 序列化并设置明确字节上限；只保留足够让方舟整理岗位、产品词和工程方法的材料。
- 不保存或记录完整原始响应。
- 来源状态按成功处理，同时增加唯一审计缺口：“招聘使用非结构化材料整理”。
- 方舟只有在 material 原文直接支持并引用对应 `evidenceId` 时，才能形成岗位、软件或工程方法事实。

以下情况不得降级，仍按失败处理：

- 法定主体、信用代码或主体归属不匹配。
- 只有解释性文本或工具使用说明。
- 空招聘内容。
- 上游工具错误、认证错误或传输错误。

## 豆包固定八类查询

继续执行最多 8 次豆包搜索，每类一次：

1. 官网产品与技术。
2. 研发/工程中心。
3. 质量体系与认证。
4. PLM/QMS/PDM。
5. Creo/CATIA/SolidWorks/CAD/PDM 招聘。
6. Abaqus/CST/CAE/有限元/电磁仿真招聘。
7. 招投标与数字化采购。
8. 扩产与融资。

第 4 条用于现有软件生态，第 5 条用于 CAD/PDM 招聘，因此允许 `PDM` 在两条查询中出现。

搜索结果不直接评级。后续装箱排序提高以下材料的优先级：

- 明确出现目标产品名。
- 明确出现对应工程方法。
- 包含完整或实质性招聘 JD。
- 来自企业官网、官方账号或明确招聘平台。
- 主体匹配为 `confirmed` 或 `probable`，且存在直接链接。

仅提及公司名称、聚合目录、无正文的中标列表降到候选尾部，但采集阶段不永久删除，以便在高价值证据不存在时仍能作为一般证据使用。

## 方舟固定容量双专槽

保持现有融资优先和行业、技术、时机、能力四类覆盖。在这些保留规则之外，新增两个尽力保留槽：

1. 一条包含明确目标产品词的证据。
2. 一条包含工程方法或实质性招聘 JD 的证据。

装箱规则：

- 同一条证据可以同时满足多个类别或专槽，只入选一次。
- 不存在符合条件的证据时不占位，也不使用泛化材料伪装产品证据。
- 产品词、工程方法和招聘 JD 的判断只用于证据排序与保留，不直接改变机会等级。
- 优先缩短低信息密度的摘要和正文，再淘汰无产品词、无方法词且只有主体名称的结果。
- 所有证据仍必须满足来源、URL、主体归属和 `evidenceId` 的现有不可变约束。
- 所有槽都受 `ARK_REQUEST_MAX_BYTES=12288` 硬上限约束。如果某槽的最小合法片段仍放不下，则不超限发送，并在研究包中记录容量缺口。

## 错误处理

- QCC 招聘未知结构但主体可验证：降级为 material，QCC 可继续为 `completed` 或因其他调用失败成为 `partial`。
- QCC 招聘主体不匹配或只有说明文本：该调用失败并明确标注，不生成材料。
- 豆包某类查询失败：遵守现有一次重试和来源降级逻辑，不用其他查询重复补偿。
- 专槽没有候选：正常继续，不视为系统错误。
- 专槽候选因硬容量无法放入：保留容量审计缺口，不放宽网关上限。
- 方舟最终仍未形成产品事实：七产品按现有规则输出“待核实”或其他合法等级，不能因召回改造而强制升级。

## 真实验收

所有自动测试通过后，使用已配置真实凭据和隔离 SQLite，对“深圳市海柔创新科技有限公司”（统一社会信用代码 `91440300MA5DR1JD5X`）执行一次 `force_refresh=true` 正式评估。不得在任务处理中重复提交。

验收记录至少包括：

- assessment ID 和总耗时。
- QCC、豆包搜索和方舟状态。
- QCC 招聘是结构化成功、material 降级、空数据还是实际上游失败。
- 原始、入选和排除证据数，以及四类覆盖数量。
- 原始资料中是否存在明确产品词、工程方法或招聘 JD；若存在，相应证据是否进入方舟入选集。
- 最终报告的直接链接情况、七产品结果和推荐产品。

验收不要求必须产生推荐产品。通过标准是：真实输入存在产品或工程方法信号时，该信号不会因适配器结构变化、宽泛搜索策略或方舟装箱顺序而技术性丢失；真实输入不存在信号时，系统如实保持“待核实”。

真实上游完整响应、网页正文、方舟完整输入输出和凭据不得写入仓库或普通日志。

## 明确边界与剩余风险

- 关键词和工程方法仍需人工维护，同义表达可能漏检。
- QCC material 降级提高兼容性，但不能保证模型一定抽取出有效事实。
- 豆包返回结果质量取决于外部索引；调用成功不等于存在相关证据。
- 方舟专槽保证“候选尽力进入输入”，不保证模型一定在输出或报告中引用。
- 本修复不改变机会评级门槛，因此真实报告继续为“待核实”可能是正确结果。
