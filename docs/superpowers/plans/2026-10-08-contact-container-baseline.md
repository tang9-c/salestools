# 联系人导入普通容器优化实施计划

依据用户在当前对话确认的方案执行。目标：普通 Linux 容器运行，不依赖 Landlock 或应用安装的 seccomp；保留 Docling、独立 Worker 和现有 MCP 接口。

## 边界

- 安全边界改为容器，不再承诺逐文件内容隔离、Sealos 同 Pod 内禁止联网或恶意进程无法逃逸进程组。
- 保留认证、任务归属、输入校验、环境白名单、离线模型、容器额度、单任务并发、超时清理、人工确认与失败持久化。
- 上传和新导入分别按 userId 每 60 秒最多 5 次；过期计数按需清理，已存在任务的幂等重试不计数。不引入 Redis、额外配置或配额平台。
- 沿用上一轮资源调整：不主动设置 AS/NPROC 上限，继承宿主限制；Sealos 上传和解析目录改用磁盘 emptyDir，保留 4Gi/2 CPU 初始验证额度。
- 禁止本地构建。主目录无关诊断和草稿文件不修改。两容器同版本，原数据库与业务数据不删除。

## 执行顺序

1. 用测试锁定默认解析入口无需 Landlock、环境及剩余限制仍生效；替换自建沙箱为单一容器运行入口，删除旧沙箱代码与不再成立的断言。
2. 在 UploadStore.reserve 和 ContactImportService.start 的共用入口加入轻量计数；HTTP 429/Retry-After，MCP 明确限流工具错误。验证幂等、用户隔离和时间窗口。
3. 更新部署模板、启动提示、现行文档及 CI；禁用 Kubernetes service-account 自动挂载，保持非 root/只读根/caps/no-new-privileges/默认 seccomp。普通容器测试不模拟成旧沙箱。
4. 本地运行解释器测试、类型检查与真实 PDF 解析；远程 CI 完成原生/全量/容器验收。审查通过后按发布流程生成同版本镜像。
5. Sealos 更新双容器和模板后，以用户授权真实简历完成上传、预览、确认入库和回读；无集群权限时明确保留该项，不能声称完成。

## 验收要点

- 普通容器启动、PDF/OCR、IPC 和任务状态持久化正常，无 Landlock/libseccomp 前置要求。
- 两个调用入口都不能绕过限流；无凭证不能调用、其他用户不能操作导入任务；重放不重复创建任务。
- 大文件、超页数、取消/超时、有限模型预算与临时清理仍有效。
- 不打印简历正文、电话邮箱、模型完整输出或凭证；不替换 Docling。

- 已验证：定向解释器测试、类型/语法/diff 检查及授权真实 PDF 默认解析；详见 `../../validation/2026-10-08-contact-container-baseline.md`。
